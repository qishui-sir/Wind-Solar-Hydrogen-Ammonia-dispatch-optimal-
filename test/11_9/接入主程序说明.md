## 3. 证书为什么仍是原问题的严格下界

11_9 的证书没有改原模型；它只改证书内部的对偶价格：

1. **基础证书**：在年度等式行 192728 的对偶价上加 \(\eta=0.03\)（等式行价格无符号限制），得 \(q=f-A_{\mathrm{cross}}^\top\pi\)；对 48/96/192 三层分区取逐块局部 MILP 下界，组装成基础证书
   \[
   \mathrm{cert}_{\mathrm{base}}=415.364094295,\qquad K\ge\lceil\mathrm{cert}_{\mathrm{base}}-10^{-5}\rceil=416.
   \]
2. **目标割**：基础证书已证明任意整数可行 \(x\) 满足 \(\sum z\ge416\)，故割 \(\sum z\ge416\) 合法。把割加回模型，取割行对偶 \(\mu=1\)、其余价格为 0；局部 \(q=0\)，得
   \[
   \mathrm{cert}_{\mathrm{cut}}=416-\mathrm{guard}_B
   =415.999998583,\qquad K\ge\lceil\mathrm{cert}_{\mathrm{cut}}-10^{-5}\rceil=416.
   \]
3. 两个证书都只使用原问题的行、符号合法的对偶价格和有限盒；没有改成本帽、没有改 \(\delta=0.5\)、没有改 \(z\) 的整数性。证书在源帽 \(31\,787\,636.626430\) USD 下成立；当前 fail 帽不宽于源帽时，同一证书仍合法。

主程序中的校验（`O1EtaCertificate` 的 `validate_eta_cache`）逐项重算：

- 源 `context.mat` / `certificate.mat` 的 `context_signature`、`model_signature`、`cap_usd`、`cap_row`；
- \(\eta=0.03\) 的源价格；
- 基础证书的 \(B\)、\(\mathrm{guard}_B\)、\(\sum\ell_j\)，与缓存的 `base_cert` 比较；
- 目标割的 96 块分区常数、割价格符号、局部界与 `cert` 比较；
- `ceil(cert-1e-5)` 与缓存 `K_lower` 比较；
- 当前 fail 帽不宽于源帽。

任何一项不通过，函数返回 `-Inf` 并给出 `reason`；主程序保留原下界（408），不会用未验证的 416。

## 4. 重算路径

默认 `main` 只读缓存，不重解。若缓存缺失或需要重算：

```matlab
% 在 main.m 的 o1_config 中设置：
o1_config.economic_eta_recompute = true;   % 强制从源 context/certificate 重算
o1_config.economic_eta_reuse_levels = true;% 复用 O1_eta_level*.mat（推荐）
```

- `economic_eta_reuse_levels=true` 且 `src/cache/O1_eta_level48/96/192.mat` 存在时，只做三层组装与目标割，通常为秒级。
- 若 level 缓存也缺失，`O1EtaCertificate` 会用 Gurobi 按 11_9 的方法重解 48/96/192 三层（每块 20/120/600 s，H=192 全整数），耗时数小时；这是 `test/11_9/run_11_9.m` 的移植版本。
- 重算会写回 `src/cache/O1_eta_certificate_cache.mat`；源 context/certificate 的签名、帽和 \(\eta\) 会写入包装。源 context 必须是当前模型/帽对应的 partition21 冻结上下文；若上下文变了，重算得到的是新上下文下的证书，不能冒充旧证书。

配置项：

```matlab
economic_eta_recompute       = false  % 默认读缓存
economic_eta_reuse_levels    = true   % 复用 level 缓存
economic_eta_eta             = 0.03   % 生产行对偶价偏移
economic_eta_levels          = [48 96 192]
economic_eta_limits          = [60 180 600]
economic_eta_threads         = 4
economic_eta_seed            = 20261017
economic_eta_allint          = true   % H=192 层全整数局部 MILP
```

## 6. 回退与边界

- **回退**：删除/重命名 `src/cache/O1_eta_certificate_cache.mat`，并把 `o1_config.economic_eta_recompute=false`；主程序会回到 partition21 的 408 下界。或直接将主缓存 `state.Keco_lower` 恢复为旧值——但主缓存是证据文件，不建议手工改；优先用文件级回退。
- **不能用的情况**：
  - `use_cache=false`：主程序不继承旧证书；`O1EtaCertificate` 返回 `-Inf`，本次仍按新分区证书计算。
  - 当前 fail 帽宽于源帽：源帽下成立的证书不能直接用于更宽的帽；函数会拒绝并在 `reason` 中说明。
  - 源 context/certificate 被替换或模型签名变化：校验失败，主程序保留原下界。
- **没有改变的事实**：416 是下界，不是可行调度；486 是可行上界，不是已证明最优；区间 `[416,486]` 仍是“已排除≤415、已见证≤486、416–485未判定”。
- **论文表述**：正文应写“主程序区间为 `[416,486]`；下界来自 11_9 的 eta/目标割证书，上界来自固定 K 的 486 次可行见证”，不能写“Keco=416”或“Keco=486 已证最优”。

## 7. 与主程序原流程的关系

```text
main
  → O1
    → 参考成本 / 经济阈值缓存
    → partition21 分块证书（原有，408）
    → O1EtaCertificate（新增）：
         加载/校验 11_9 缓存 → 416
         feasibility.K_lower = max(原下界, 416) = 416
    → certify（原有）：
         使用 feasibility.K_lower=416
         rejected.source = eta_certificate_global_count
         upper 从 486 次可行见证取得
    → 输出 [416,486]；state.Keco_lower=416、Keco_upper=486 写回主缓存
```

partition21 的 408 证书仍保留在 `state.partition21.certified` 与 `state.caps` 中；它不再是主下界，但作为独立证据和回退路径保留。两套证书的共同前提是同一冻结分区上下文、同一成本帽和同一 \(z\) 整数域。
